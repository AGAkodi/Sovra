# Throttle for NEAR - Implementation Log

## Phase 0: Orientation, Rules, and Research
- **Timestamp**: 2026-11-06 09:10 UTC
- **Decisions**:
  - Confirmed testnet-only architecture with deterministic risk engine and NEAR smart contract vault.
  - LLM outputs will propose tasks and payments, but will never authorize money movement directly.
  - Contract will enforce an attestation trust model where decisions are signed by an authorized policy signer or verified on-chain, binding `vault_id`, `request_id`, `recipient`, `amount`, `risk_band`, `authority_level`, `policy_version`, and `expiry`.
  - UI will strictly follow Section 8 specifications and the Unslop aesthetic guidelines (calm palette `#0B1018`, raised panels `#121B27`, borders `#273446`, cyan `#4CC9E8`, amber `#F2B544`, red `#EF6464`, green `#38C98B`, 4px spacing, tabular numbers, quiet chrome, zero AI-slop).
- **Toolchains**:
  - Node.js v26.13.0, npm 11.20.0 (invoked via `npm.cmd` on Windows due to PowerShell execution policy).
  - Rust toolchain with `wasm32-unknown-unknown` target for smart contracts.
- **Blockers & Mitigations**:
  - PowerShell execution policy blocks `.ps1` wrapper scripts; mitigated by invoking `.cmd` or explicit node runners.
  - Rust toolchain installation initiated via `rustup-init.exe` with minimal profile.


## Phase 1: Chain path fixes (contract ↔ backend)
- **Timestamp**: 2026-11-08 UTC
- **Problems found**:
  - Backend agent never called NEAR; it fabricated `tx-<uuid>` hashes and marked payments `succeeded`. Approvals did the same.
  - `near/client.ts` sent argument names the contract does not accept, attached 1 yoctoNEAR to a non-payable method (function-call keys cannot attach deposits anyway), and read env vars before dotenv loaded.
  - Contract signature check passed the 33-byte `PublicKey::as_bytes()` (curve prefix + key) where 32 bytes are required, so every signed request would panic.
  - Attestation signer used a fresh random key each start instead of `POLICY_SIGNER_PRIVATE_KEY`.
  - With `policy_signer_pk: null` the contract skipped verification and trusted the agent's self-reported risk.
  - Signed message omitted policy version and network.
- **Decisions**:
  - Attestation message: `throttle-attestation-v1|chain_id|vault|request_id|recipient|amount_yocto|risk|authority|policy_version|expiry_ns`. Request IDs restricted to `[A-Za-z0-9_-]{1,64}` so `|` cannot create ambiguity.
  - Signature is mandatory; no unsigned path. Owner no longer bypasses the agent allow-list on `request_payment`.
  - Level-6 and over-cap requests are still signed and submitted, so the vault records the refusal on-chain (checked before the balance check).
  - Held requests get a 1-hour approval window (`APPROVAL_TTL_NS`), separate from the 5-minute attestation expiry. `approve_request` refuses while frozen.
  - Available balance excludes the storage-staking reserve.
  - Timestamps in views are `U64` (JSON strings) to avoid JS precision loss.
  - Backend has two explicit modes: `testnet` (real broadcast, status read back from `get_request`) and `simulation` (labelled, `sim-` hashes, UI shows "Simulated, not onchain"). In testnet mode owner actions (approve/reject/freeze/policy) return 409: they need the owner wallet. Vault state read failure → 503, fail closed.
  - Background reconciler (15 s) re-reads open testnet requests; `POST /payment-requests/:id/sync` for on-demand sync.
- **Tests**:
  - Backend: 24/24 (`npm test`), including test vector shared with the contract and mocked-RPC tests of the testnet path.
  - Contract: `src/tests.rs` (21 tests) using signatures generated by the backend signer.
  - Contract wasm release build OK (456,662 bytes).
- **Blockers**:
  - Host `cargo test` on Windows GNU toolchain needs MinGW `dlltool` + `as` (getrandom raw-dylib). Not installed; see below for status.
  - Not yet deployed to testnet; no real tx hashes yet. Owner wallet integration (wallet-selector) still missing.
- **Contract test status**: `cargo test` cannot build on this machine yet. `--cfg getrandom_backend="windows_legacy"` gets past getrandom, but near-sdk's unit-testing runtime also compiles native code (`cmake` crate), which needs MSVC Build Tools or MSYS2 MinGW. The tests are written but **not yet run**.
- **Update 2026-11-08**: CI added (`.github/workflows/ci.yml`). First run on `chain-path-and-ci` passed all jobs, including contract `cargo test` (21 tests) and the wasm release build on ubuntu-latest: https://github.com/AGAkodi/Sovra/actions/runs/42498141060
